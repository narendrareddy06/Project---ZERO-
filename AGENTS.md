# Project ZERO — Development Rules

1. Read docs/PRD.md (or docs/Project_ZERO_PRD.docx) before implementing features.
2. Treat the PRD as the authoritative product specification.
3. Implement one approved stage at a time.
4. Preserve existing working code.
5. Enforce permissions in application code, not only in AI prompts.
6. Run tests after every meaningful change and report exact results.
7. Never claim a feature works without verification.
8. Never send real external messages during tests.
9. Never introduce paid dependencies or exceed the ₹0 budget target without explicit user direction.
10. Report changes, test results, blockers, assumptions, and remaining work.
11. Require user approval for every external message and material commitment.
12. Do not automate LinkedIn scraping or messaging.
13. Do not fabricate evidence, prospects, outcomes, testimonials, or revenue.
14. Preserve opt-outs and do-not-contact records across runs.
